# TuneGraph — Weekend MVP Engineering Handoff

## 1. Product Summary

**TuneGraph** is a modern, interactive music relationship explorer inspired by TuneGlue.

A user searches for an artist, sees that artist as a node in a force-directed graph, and can continuously expand related artists outward. Selecting an artist shows lightweight metadata, top tracks, genres/tags, and—where available—a short audio preview or outbound listening links.

The product should feel exploratory first, informational second.

The MVP should be intentionally small enough to ship in a weekend.

---

## 2. Core Product Goal

Create a fast, visually satisfying way to answer:

> “What music is connected to this artist, and where can I wander from here?”

The graph should encourage discovery through repeated expansion rather than playlists, feeds, or algorithmic recommendations.

---

## 3. MVP Scope

### Required

1. Search for an artist by name.
2. Render the selected artist as the initial graph node.
3. Fetch approximately 5–8 similar artists.
4. Render similar artists as connected nodes.
5. Allow selecting any node.
6. Allow expanding any artist node to fetch another 5–8 similar artists.
7. Reuse existing graph nodes rather than duplicating them.
8. Show a compact artist detail panel.
9. Display top tags/genres.
10. Display top tracks.
11. Provide an audio preview when available.
12. Provide outbound links to major music services.
13. Keep graph state client-side.
14. Cache external API responses.

### Explicit Non-Goals

Do **not** build these during the MVP:

- User accounts
- Authentication/login
- Saved graphs
- Playlists
- Recommendations generated by AI
- Embeddings/vector search
- Social features
- Mobile-native apps
- Database persistence
- Full-track playback
- Spotify account integration
- Complex genre genealogy
- Collaborative filtering
- Production-scale infrastructure

If time remains, polish the graph rather than adding more product surface.

---

## 4. Suggested Stack

### Frontend

- React
- TypeScript
- D3.js force simulation

Alternatives such as Cytoscape.js, Sigma.js, or React Flow are acceptable if the engineer prefers them, but D3 provides the most direct control over TuneGlue-style behavior.

### Backend

- Python
- FastAPI
- HTTPX for async external API requests

### State

MVP graph state remains entirely in the browser.

No database required.

### Cache

Start with an in-memory TTL cache.

Example:

```text
artist search: 15–60 min
artist metadata: 24 hr
similar artists: 24 hr
top tracks: 6–24 hr
MusicBrainz metadata: 7 days
preview resolution: 24 hr
```

Redis can be added later if the application becomes multi-instance.

## 5. External API Strategy

### 5.1 Last.fm — Primary Relationship Engine

Use Last.fm as the primary source for music relationships.

Relevant methods:

```text
artist.search
artist.getSimilar
artist.getInfo
artist.getTopTracks
artist.getTopTags
tag.getSimilar            # future / optional
tag.getTopTracks          # future / optional
```

Primary MVP uses:

```text
artist.search
artist.getSimilar
artist.getTopTracks
artist.getTopTags
```

### Authentication

For the public read operations needed by this MVP:

- Application API key required.
- User login is not required.
- User OAuth/session authentication is not required.

Keep the Last.fm API key server-side.

### Important

Last.fm should be treated as the source of relationship strength.

Store the similarity score returned by Last.fm on graph edges where available.

Example:

```json
{
  "source": "radiohead",
  "target": "portishead",
  "similarity": 0.73
}
```

This can later drive:

- edge width
- edge opacity
- force distance
- ranking

Do not over-design those visual encodings in V1.

---

## 5.2 MusicBrainz — Identity + Metadata Normalization

Use MusicBrainz primarily to avoid relying exclusively on artist names as identity.

Preferred artist identity:

```text
MusicBrainz Artist ID (MBID)
```

Use MusicBrainz for:

- canonical artist IDs
- canonical artist name
- aliases
- disambiguation
- external identifiers
- supplementary metadata

Last.fm responses may already include MBIDs. Use them whenever available.

### Authentication

Normal public lookups:

- No API key required.
- No user authentication required.

### Client Requirements

Send an appropriate application `User-Agent`.

Example:

```text
TuneGraph/0.1 (contact@example.com)
```

### Rate Limiting

MusicBrainz asks clients to avoid aggressive traffic.

Design around approximately:

```text
1 request / second / IP
```

Use caching aggressively.

MusicBrainz is **not** required for every graph expansion if Last.fm already provides enough information.

---

## 5.3 Apple Music — Preview / Catalog Resolution

Apple Music is the preferred first experiment for resolving playable previews.

Desired behavior:

```text
artist + track
    ↓
Apple Music catalog lookup
    ↓
preview URL if available
```

Do not make the entire MVP dependent on preview availability.

If preview resolution fails, the UI should still provide:

```text
Open in Apple Music
Open in Spotify
Search on YouTube
```

### Authentication

Catalog functionality generally relies on an Apple developer token.

User authorization should **not** be required for the MVP unless the implementation specifically moves into subscriber-only playback.

Avoid building MusicKit account authorization in V1.

### Architecture Requirement

Wrap audio providers behind an internal provider abstraction.

Example:

```python
class PreviewProvider:
    async def get_preview(
        self,
        artist: str,
        track: str
    ) -> PreviewResult | None:
        ...
```

Initial implementation:

```text
AppleMusicPreviewProvider
```

This protects the application if Apple changes availability or another provider becomes preferable.

---

## 5.4 Spotify — Optional Only

Spotify is **not** a core dependency for V1.

Use it primarily for outbound links if convenient.

Possible future uses:

- open artist in Spotify
- open track in Spotify
- user library integration
- playlist creation

Do not depend on Spotify's `preview_url` field for MVP playback.

Preview URLs may be absent and are deprecated/unreliable as a product foundation.

### Authentication

Server-to-server public metadata may use client credentials where supported.

User-specific functionality requires OAuth scopes.

No Spotify OAuth should be added to the weekend MVP.

## 7. Backend API

Keep the internal API extremely small.

### Search Artists

```http
GET /api/artists/search?q=radiohead
```

Example response:

```json
{
  "artists": [
    {
      "id": "mbid-or-generated-id",
      "mbid": "optional-mbid",
      "name": "Radiohead",
      "image_url": null
    }
  ]
}
```

---

### Get Artist

```http
GET /api/artists/{artist_id}
```

Response:

```json
{
  "id": "artist-id",
  "mbid": "mbid",
  "name": "Radiohead",
  "tags": [
    "alternative",
    "alternative rock",
    "art rock"
  ],
  "external_urls": {
    "lastfm": "...",
    "spotify": null,
    "apple_music": null
  }
}
```

---

### Get Similar Artists

```http
GET /api/artists/{artist_id}/similar?limit=8
```

Response:

```json
{
  "artist_id": "radiohead-id",
  "artists": [
    {
      "id": "portishead-id",
      "mbid": "...",
      "name": "Portishead",
      "similarity": 0.73
    },
    {
      "id": "the-smile-id",
      "mbid": "...",
      "name": "The Smile",
      "similarity": 0.69
    }
  ]
}
```

---

### Get Top Tracks

```http
GET /api/artists/{artist_id}/tracks?limit=5
```

Response:

```json
{
  "tracks": [
    {
      "name": "Everything in Its Right Place",
      "listeners": 1234567
    }
  ]
}
```

---

### Resolve Preview

```http
GET /api/artists/{artist_id}/tracks/{track_name}/preview
```

Response:

```json
{
  "available": true,
  "preview_url": "...",
  "duration_seconds": 30,
  "provider": "apple_music"
}
```

Unavailable:

```json
{
  "available": false,
  "preview_url": null,
  "provider": null
}
```

A failed preview lookup must never break the artist panel.

## 8. Graph Data Model

### Node

```ts
type ArtistNode = {
  id: string;
  mbid?: string;
  name: string;

  expanded: boolean;
  loading: boolean;

  tags?: string[];
  imageUrl?: string;
};
```

### Edge

```ts
type ArtistEdge = {
  id: string;
  source: string;
  target: string;
  similarity?: number;
};
```

### Graph State

```ts
type MusicGraph = {
  nodes: Map<string, ArtistNode>;
  edges: Map<string, ArtistEdge>;
  selectedNodeId?: string;
};
```

## 9. Identity / Deduplication Rules

Avoid duplicate nodes.

Preferred identity hierarchy:

```text
1. MusicBrainz ID
2. Last.fm canonical URL
3. normalized artist name
```

Normalized name fallback:

```text
lowercase
trim whitespace
collapse repeated spaces
Unicode normalize
```

Do not rely on normalized names when an MBID exists.

Edge IDs should be deterministic.

Example:

```text
min(source,target) + "::" + max(source,target)
```

This prevents duplicate relationships.

## 10. Primary User Flow

### Initial State

Display:

```text
Explore music

[ Search for an artist... ]
```

No graph required before searching.

---

### Search

User enters:

```text
Radiohead
```

Select an artist result.

The application:

1. clears previous graph
2. creates Radiohead node
3. centers it
4. requests similar artists
5. renders returned nodes
6. animates graph settling

---

### Graph Exploration

User clicks:

```text
Portishead
```

The node becomes selected.

Display an artist panel.

The graph should not automatically expand every selection.

Panel exposes:

```text
Expand
```

Selecting **Expand**:

```text
GET /similar
```

New nodes and edges enter the graph.

Existing nodes are reused.

## 12. Graph Interaction Requirements

Required:

- click/tap node to select
- expand selected node
- zoom
- pan
- drag nodes
- maintain selected state
- newly added nodes animate into graph
- avoid duplicate nodes
- avoid duplicate edges

Recommended:

- larger nodes for nodes with more known connections
- subtle edge strength based on similarity
- highlight selected node
- deemphasize distant graph elements while a node is selected

Avoid:

- excessive labels
- rainbow color encoding
- nonstop animation
- huge initial expansions

Target expansion:

```text
5–8 nodes per click
```

The graph should grow intentionally rather than explode.

---

## 13. Force Simulation

Suggested initial forces:

```text
forceLink
forceManyBody
forceCenter
forceCollide
```

Similarity may eventually affect link distance:

```text
stronger similarity
    ↓
shorter graph distance
```

For MVP, a fixed distance is acceptable.

Prioritize stability over clever physics.

---

## 14. Loading Behavior

When expanding an artist:

- visually mark the node as loading
- keep graph interactive
- prevent repeated expansion requests
- gracefully handle API failure

Possible UI:

```text
Radiohead
   ◌
```

On success:

```text
expanded = true
loading = false
```

---

## 15. Error Handling

### Search Failure

Display:

```text
Couldn't search right now. Try again.
```

### Similar Artist Failure

Do not break graph.

Display near selected artist:

```text
Couldn't load more connections.
```

Allow retry.

### Preview Failure

Silently fall back to external listening links.

Preview playback is enhancement—not core functionality.

### Rate Limits

Backend should translate provider-specific rate-limit responses into:

```http
429 Too Many Requests
```

Include optional retry information.

---

## 16. External API Isolation

Do not allow provider response shapes to leak into frontend models.

Recommended structure:

```text
app/
  api/
    routes/
      artists.py

  services/
    lastfm.py
    musicbrainz.py
    apple_music.py

  models/
    artist.py
    track.py
    graph.py

  cache/
    cache.py
```

Each provider should map into internal models.

Example:

```python
class Artist:
    id: str
    mbid: str | None
    name: str
```

This makes provider replacement substantially easier.

## 20. Definition of Done

The weekend MVP is done when all of these statements are true:

- A user can search for an artist.
- Search results are selectable.
- Selecting an artist creates a graph.
- The initial graph contains related artists.
- Relationships are represented by visible edges.
- Selecting a node opens artist information.
- Clicking Expand adds related artists.
- Existing artists are not duplicated.
- Existing relationships are not duplicated.
- The graph remains usable after at least 5 expansion operations.
- API failures do not destroy graph state.
- External provider secrets are server-side.
- The app can run locally from documented setup instructions.

Preview playback is a bonus acceptance criterion, not a blocker.

     |                 |

     |                 |

Node types:

```ts

  | ArtistNode
  | GenreNode;
```

Possible interactions:

```text
Artist → related artist
Artist → genre
Genre → related genre
Genre → representative artists
```

This turns TuneGraph from a TuneGlue recreation into a general music knowledge explorer.

## 23. Product Principle

The main quality metric is not:

```text
How much information can we display?
```

It is:

```text
Does clicking one more node feel irresistible?
```

If the graph itself is enjoyable to wander through, the MVP succeeded.
